# DayCoin 2 合约设计草案 v0.1

状态：本地原型，**未审计、未部署测试网或主网**。目标链为 Arbitrum One，先在 Arbitrum Sepolia 验证。

## 核心规则

1. GitHub 资格通过链下核实；当前首期规则为账户至少 7 年、累计 Star 至少 10、第三方合并 PR 至少 10、Followers 至少 10（AND）。
2. 链下认证服务以 EIP-712 签发对「身份标识、钱包地址、到期时间」绑定的登记许可。EIP-712 的域包含 chainId 和验证合约地址。
3. 链上每个身份标识只能登记一次，每个钱包也只能登记一份。登记从当时开始累计奖励，**不补发注册之前的时间**。
4. 每个已登记的身份按秒累计等价于每天 1 DC2（18 位小数）。多日后可一次 Claim；计算累计总权益减已铸币总量，避免多次领取的舍入损耗。
5. 登记后资格永久有效，不复审、不可撤销。无 Owner、无管理员 Mint、无升级、无暂停或资金救援。
6. 代币是普通可转账 ERC-20，**转账代币不转移未来领取权**。DC1 和 DC2 完全不同、没有兑换承诺。
7. 本版本不接受 ETH 抵押。

## 简化设计的代价

- **发行签发者是关键的中心化信任点。** 合约只验证签名，不知道 GitHub 账户的真伪、账户年龄、Star、PR 或 Followers。签发服务须保证同一 GitHub 数字 ID 只发出一个有效身份标识；否则不同随机标识能对应同一个账户并造成多领。合约无法自己发现此情况。
- 为避免公开 GitHub 数字 ID 被简单哈希反查，合约身份标识应为不可猜测的随机 nullifier，由服务端稳定维护账户与该 nullifier 的一对一关系。当前**没有实现**该服务端发行/储存系统；在它完成并接受安全审查前不可签发真实资格。
- Issuer 地址固定、不可轮换；若签发私钥泄露，可给大量假身份永久开户；若丢失则无法登记新用户。正式上线前必须决定密钥安全及恢复策略，或改变合约设计。
- 钱包绑定不可更换。若私钥遗失，既有资格和未领收益无法迁移到新钱包。是否实现安全恢复是**主网发布前的待定重要问题**。
- 当前 ERC-20 没有 Burn 接口、总量上限或停止发行机制，符合永久累计的实验方向，但无限期发行带来长期供应量增长。
- 由于 GitHub 数字身份与自然人不等价、Star 与 PR 可刷，项目不能声称实现真正一人一份。

## 本地合约接口

- `constructor(address issuer)`：部署时固定签发者。
- `register(bytes32 identity, uint256 deadline, bytes signature)`：签名验证、唯一性检查、开始累计。
- `pending(address recipient)`：可领取奖励。
- `claim()`：把全部已累计未铸币收益铸给登记钱包。
- `positions(identity)`、`identityOf(wallet)`：公开登记状态；不记录 GitHub 用户名。

测试：`node --test test/dc2-contract.test.mjs`。
