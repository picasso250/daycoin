# DayCoin 2 合约设计草案 v0.2

状态：本地原型，**未审计、未部署测试网或主网**。目标链为 Arbitrum One，先在 Arbitrum Sepolia 验证。

## 核心规则

1. GitHub 资格通过链下核实；当前首期规则为账户至少 7 年、累计 Star 至少 10、第三方合并 PR 至少 10、Followers 至少 10（AND）。
2. 链下认证服务以 EIP-712 签发对「GitHub 数字 ID、钱包地址、到期时间」绑定的登记许可。EIP-712 的域包含 chainId 和验证合约地址。
3. 链上每个 GitHub 数字 ID 只能登记一次，每个钱包也只能登记一份。登记从当时开始累计奖励，**不补发注册之前的时间**。
4. 每个已登记的身份按秒累计等价于每天 1 DC2（18 位小数）。多日后可一次 Claim；计算累计总权益减已铸币总量，避免多次领取的舍入损耗。
5. 登记后资格永久有效，不复审、不可撤销。无 Owner、无管理员 Mint、无升级、无暂停或资金救援。
6. 代币是普通可转账 ERC-20，**转账代币不转移未来领取权**。DC1 和 DC2 完全不同、没有兑换承诺。
7. 本版本不接受 ETH 抵押。

## 简化设计的代价

- **发行签发者是关键的中心化信任点。** 合约只验证签名，不知道 GitHub 账户的真伪、账户年龄、Star、PR 或 Followers。合约直接以 GitHub 数字 ID 去重；即使签发者再次给同一 ID 签名也无法重复登记，但签发者仍能替不存在或不合格的 ID 签发资格。
- **参与者自愿公开身份与钱包的永久对应关系。** 直接上链 GitHub 数字 ID，不再维护随机 nullifier 与私密映射数据库。网站在申请前必须明确提示：绑定将长期公开、可被索引，链上历史通常无法删除；建议使用专门的钱包。
- Issuer 地址固定、不可轮换；若签发私钥泄露，可给大量假身份永久开户；若丢失则无法登记新用户。正式上线前必须决定密钥安全及恢复策略，或改变合约设计。
- 钱包绑定不可更换。若私钥遗失，既有资格和未领收益无法迁移到新钱包。是否实现安全恢复是**主网发布前的待定重要问题**。
- 当前 ERC-20 没有 Burn 接口、总量上限或停止发行机制，符合永久累计的实验方向，但无限期发行带来长期供应量增长。
- 由于 GitHub 数字身份与自然人不等价、Star 与 PR 可刷，项目不能声称实现真正一人一份。

## 公开身份与无挑战设计

GitHub 用户主动选择参与时，公开数字 ID 与钱包地址。链上直接防止相同 ID 再次登记。不设置任何人挑战、管理员撤销、定期复核或事后惩罚机制；这不是完全抗女巫机制。申请前应有明确的知情确认，尤其解释公开钱包和身份的可关联性。

## 本地合约接口

- `constructor(address issuer)`：部署时固定签发者。
- `register(uint256 githubId, uint256 deadline, bytes signature)`：签名验证、唯一性检查、开始累计。
- `pending(address recipient)`：可领取奖励。
- `claim()`：把全部已累计未铸币收益铸给登记钱包。
- `positions(githubId)`、`githubIdOf(wallet)`：公开、可互查的身份与钱包关系；不记录可修改的 GitHub 用户名。

测试：`node --test test/dc2-contract.test.mjs`。
