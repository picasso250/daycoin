# DayCoin 2 (DC2) — 项目计划 v0.2

> **状态：设计草案 / 未发行 / 未审计**  
> 日期：2026-11-12  
> 路径：`docs/DC2-PLAN.md`  
> 项目：DayCoin · One Coin a Day

## 0. 一句话定位

**DC2 是部署在 Arbitrum One、以成熟 GitHub 账号及其可验证开源贡献作为首期准入依据的平等每日发行实验。**

首期服务长期参与开源技术生态的建设者。GitHub 账号不能证明唯一自然人，目标是提高批量伪造资格的时间与经济成本，而非宣称解决所有女巫攻击。

## 1. 确认与待议

### 已确认

1. **目标链 Arbitrum One**；先在 Arbitrum Sepolia 验证。
2. **DC1 与 DC2 独立**：独立发行源、合约、代币标识、供应量，不自动兑换或继承余额。
3. **首期 GitHub 资格**：四项均需满足——账户 ≥7 年、原创仓库累计独立 Star ≥10、第三方已合并 PR ≥10、Followers ≥10。
4. **合格身份平等发行**：拟定每天累计 1 DC2，不按声望加权；支持延后批量 Claim。
5. **永久资格**：通过首次 GitHub 验证并完成链上登记后，永久有效；不周期续验、不撤销。
6. **门槛只降不升**：后续调整可扩大准入，不对既有永久资格追溯收紧。
7. **公开透明**：资格规则、验证实现、合约权限、风险和实验数据公开；不承诺价格或收益。

### 尚未决定

- GitHub 指标的**可信计数方式**、异常/缺失数据处理；四个门槛已确定，不使用加权评分。
- 是否有押金；目前倾向不再设置 DC1 式 0.1 ETH 准入门槛。
- 钱包换绑、恢复、冷却期与资格转移机制。
- 后续其他身份入口与跨入口重复领取的防护。
- 发行精度、开始时间、上限、停发条件和不可升级性。
- 签发者权限、申诉制度与隐私设计。

## 2. 与 DC1 的边界

| 资产 | 网络 | 身份 | 关系 |
|---|---|---|---|
| 原生 DC1 | Ethereum Mainnet (1) | 第一代原生发行源 | 原样保留，不迁移 |
| 官方桥接 DC1 | Arbitrum One (42161) | 对应 L1 DC1 的桥接表示，无独立奖励发行 | 仍是 DC1，绝不重命名为 DC2 |
| 原生 DC2（拟议） | Arbitrum One (42161) | 全新独立发行实验 | 不兑换、不锚定、不承继 DC1 余额 |

现有仓库 README 列出的地址：

- Ethereum 原生 DC1：`0x5473aac7ed5c5b14c4E7e2c8a8844f8e3FC92715`
- Arbitrum 桥接 DC1：`0xDa7f5A3e68145Ad5125216d40D58729bEF5275f7`

任何官网、钱包指引、文档均须同时标明网络、chainId、合约地址、原生/桥接属性及版本；不能凭符号判断资产身份。

**DC1 复盘**：L1 日常小额交互的 Gas 摩擦较高，但 DC1 按秒累计、允许延后 Claim，不能误称为每天必须执行一笔链上交易。其 ETH 押金提高地址成本，不等于证明人格唯一。DC2 因此探索低成本链与历史信誉准入。

## 3. GitHub 资格模型

### 3.1 首期准入标准（已确定）

| 必要条件（全部 AND） | 门槛 | 核验要求 |
|---|---:|---|
| GitHub 账户历史 | ≥7 个完整公历年 | 用不可变 User ID 及账户创建时间核验 |
| 原创项目累计 Star | ≥10 | 非 Fork、自己拥有的仓库；核实外部独立 Star |
| 第三方已合并 PR | ≥10 | 实际合并至独立第三方仓库，不能用自己仓库刷量 |
| Followers | ≥10 | GitHub 用户资料 followers 字段；承认社交指标容易刷 |

- 四个条件**必须同时满足**；不设替代路径、不设百分制、无额外仓库数量或贡献月份硬门槛。
- 严格起步、未来只放宽：每次降门槛应公开新规则版本与生效时间；已登记资格永远有效，降低门槛不让老用户重复领币。
- 不把“资格稀缺”等同于代币价格或总供应量稀缺。
- 当前公开 GitHub API 预分析无法完全证明独立 Star 与第三方 PR 的完整历史；**不得将展示数字直接用于永久资格签发**。

### 3.2 数据真实性

- 登录证明当前操作者控制账户，不证明唯一自然人。
- 用稳定 GitHub 数字 ID，而非可改名的 login。
- 热力图、仓库数、Star、PR 均可被操纵；私有贡献展示设置会导致漏算。
- 自建仓库自合并的 PR 不作为强证据；外部贡献和维护者独立性要审查。
- 外部 Star 的来源、历史时间点、贡献跨度等数据需先验证 API 可获得性。
- 账号交易、盗号、旧号农场无法靠 OAuth 一项排除；鉴于资格永久且不可撤销，上线前的首次验证应更审慎，明确这是设计取舍。

### 3.3 威胁模型

| 攻击 | 初步防护 |
|---|---|
| 批量注册/养号 | 账户年龄与跨时期贡献组合 |
| 刷 Star/互刷 | 独立来源、异常集中度分析，限制 Star 权重 |
| 自建仓库刷 PR | 检查仓库与维护者独立性 |
| 买卖/盗取旧 GitHub 账号 | 首次资格验证严格审查；已经登记的资格不撤销，承认残余风险 |
| 一个 GitHub 身份绑定多个钱包 | GitHub 数字 ID 直接上链并唯一登记 |
| 验证服务伪造资格 | 规则开源、可审计签发日志、密钥隔离、研究多方验证 |
| 签名重放/跨链复用 | EIP-712 域隔离、chainId、合约地址、nonce、过期时间 |

所有防护应评估误伤率，不可宣称完全杜绝女巫攻击。

## 4. 系统设计

```text
GitHub OAuth（最小权限）
    ↓
资格索引和评分服务（GitHub API + 规则版本 + 缓存）
    ↓
钱包签名（chainId / 合约 / 钱包 / 截止时间）
    ↓
资格证明签发（限期、一次性）
    ↓
Arbitrum DC2 合约
    ├─ 唯一资格登记与防重复
    ├─ 按时间累计（拟议 1 DC2 / 24h）
    ├─ 随时 Claim，可积攒
    └─ 钱包恢复/换绑（如支持，不能新增或复制资格）
```

### 合约的最小边界

- 公开可审计已登记身份、发行量及领取量，避免泄露不必要身份数据。
- 凭证明确绑定 chainId、合约、钱包、资格标识、规则版本、有效期、nonce。
- 同一资格标识不得创建两个并行累计仓位；换绑时不能复制或重置奖励。
- 第一版不引入收益、质押、兑换、排名和复杂的可变发行倍率。
- **已决定公开绑定**：GitHub 数字 ID 及钱包地址直接上链。用户自愿选择参与，申请前应提示长期公开且无法从链上历史删除。
- 如果中心化签发者能决定资格，它就有实际准入权。即使 ERC-20 无 owner，也不能声称完全无信任。
- 可研究签发密钥轮换、未使用凭证过期与新登记暂停；**不得赋予管理员撤销已登记永久资格的权限**。

### GitHub 服务与隐私

- OAuth 只要必要权限，不索取写入仓库的授权。
- 默认不公开钱包与 GitHub 用户名对应表；制定最小化数据保留规则。
- GitHub API 有速率限制、查询成本和字段缺失，需缓存、重试、队列及错误分类。
- 已登记用户的链上 Claim 应尽量不依赖 GitHub 服务即时可用。

## 5. 永久资格（已确定）

**一次验证，永久有效。** GitHub 账户通过资格检查并在链上成功登记后，永久获得该身份对应的 DC2 累计发行资格：

- 不做周期续验；之后的 Claim 不需要再次登录 GitHub，也不依赖验证服务持续在线。
- 不设置管理员撤销已登记资格、冻结已获得代币或追回 ERC-20 余额的功能。
- 每个已登记身份永远只对应一份累计额度；更换钱包（若后续支持）只能迁移控制权，不能复制身份、重复发行或重置累计时间。
- 仍允许首次认证时拒绝未达标账户、让未使用的签名凭证按期失效；这不等于撤销已登记资格。
- 承认永久资格带来的账号交易、盗号、刷号漏网等不可逆风险，重点做好**首次验证**而不是引入后续管理权。

## 6. 分阶段路线与验收

### P0 制度与指标（不发行代币）

- [ ] 固定 DC1 / DC2 命名和地址展示规范。
- [ ] 明确 GitHub 证据定义、评分算法、边界情况及女巫模型。
- [ ] 调查 GitHub API 对独立 Star、10 个第三方合并 PR、Followers 的可得性、验证成本和服务额度。
- [ ] 实现永久资格原则，明确签发权限和数据保护原则。

**验收**：给定同一组公开数据，资格判定可复现；不能可靠获取的字段明确标记。

### P1 离线资格原型

- [ ] OAuth、稳定账户 ID、数据采集、缓存与评分实现。
- [ ] 对合格、边缘、刷量账号样本回测，记录误判。
- [ ] 展示通过/不通过及理由，不要求用户提供高权限 Token。
- [ ] 记录规则版本与可审计日志。

**验收**：可重复运行并解释结果，异常账号和缺失数据有处理策略。

### P2 Arbitrum Sepolia

- [ ] 编写GitHub 数字 ID 与 EIP-712 资格签名设计。
- [ ] 实现登记、时间累计、Claim，覆盖整数精度和时钟边界测试。
- [ ] 测试签名凭证过期、重复注册、跨链重放、钱包换绑、恶意签发与验证服务停机；确认已登记资格不可撤销。
- [ ] 公布测试合约、测试套件和可复现部署记录。

**验收**：关键不变量验证通过，明确权限和升级策略。

### P3 小规模试点

- [ ] 多类型贡献者参与，不只选择高 Star 开发者。
- [ ] 统计资格通过率、误判率、可疑群组、Gas 和领取习惯。
- [ ] 独立审查合约、签名域、密钥和隐私风险。
- [ ] 公布风险和申诉办法。

**验收**：没有未解释的高严重度问题，参数选择有实测依据。

### P4 Arbitrum One 上线决策

- [ ] 决定正式名字、Symbol、发行参数、官网风险提示。
- [ ] 发布白皮书、开源代码、审查和测试报告。
- [ ] 完成前述验收后才决定是否实际部署，不强制赶进度。
- [ ] 持续观察异常登记、发行量及链上成本；不得通过监测结果撤销已登记资格。
- [ ] 保证 DC1 独立运行，绝不承诺 DC2 接管 DC1 价值。

## 7. 成功指标

- 首次资格判定可复现比例及可解释程度。
- 不同贡献路径的通过率、假阳性和假阴性。
- 异常账户阻断能力与误伤情况。
- 验证开销、领取 Gas 的中位数及尾部值。
- 30/90 天留存和批量 Claim 使用情况。
- 签发者权限、资格争议和处理过程的透明度。

**不以币价、交易量、市值作为主要 KPI。**

## 8. 风险声明

1. GitHub 信誉不等于人格证明，一 GitHub 账户不等于一个自然人。
2. 开源指标有选择偏差；大量优秀工程师可能没有公开贡献。
3. Arbitrum One 的底层信任假设与 Ethereum L1 有差异。
4. 资格服务和签发者带来中心化与审查风险。
5. DC2 是实验性代币，不保证价格、流动性、收益或 DC1 兑换权。
6. 当前全部数值阈值均为研究草案，不构成上线承诺。

## 9. 下一步，先不写正式合约

1. **API 可行性与采样**：确认创建时间、外部 Star、合并 PR、跨月贡献能否稳定验证。
2. **资格规则 v0.2 与攻击模型**：通过样本评估四项 AND 门槛的覆盖率、误判和刷号成本；如需修改，仅放宽阈值。
3. **无代币资格模拟器**：先优化通过率与抗刷号表现，再决定签发设计。
